# llm-wiki — step-by-step guide

A schema-driven LLM Wiki: immutable `raw/` sources are compiled by an LLM into a `wiki/` folder that
is a valid Open Knowledge Format (OKF v0.2) bundle. It is **stateless** — the LLM writes each
Markdown page directly, and those pages are the only source of truth. The scripts orchestrate the
model, discover raw files, scan the pages to count mentions, regenerate `index.md`, and lint.

For a zero-setup, script-free variant (you drive it by asking the agent, no Python), see the sibling
`llm-wiki-lite` skill (`../llm-wiki-lite/README.md`).

---

## 1. How it works (the mental model)

```
raw/*.md ──(LLM writes pages, per SCHEMA + templates)──▶ wiki/**/*.md ──(util.py scans)──▶ index.md
   immutable                judgment                         source of truth    bookkeeping
```

- The **LLM does judgment**: reading a source, resolving entities, deciding what is a claim, and
  writing the page prose and citations.
- The **scripts do bookkeeping**: discovering raw files, supplying exact frontmatter metadata,
  counting mentions across the pages, regenerating `index.md`, and linting.
- `ingest` and `query` call the LLM. `lint` and `index` do not (they only read/scan the pages).
- There is **no `.wiki-state.json`** and no byte-identical rebuild — the point of dropping state is
  that it does not scale to hundreds of articles and did not improve the result.

## 2. Prerequisites

- **Python 3.10+**.
- For `ingest` / `query` only: an LLM provider.
  - `pip install anthropic` (default) — then `export ANTHROPIC_API_KEY=…`, or run `ant auth login`.
  - or `pip install openai` — then `export OPENAI_API_KEY=…` and set `LLM_MODEL`.
- `lint` and `index` need neither the package nor a key.

Environment variables (all optional unless noted):

| Variable | Meaning | Default |
|---|---|---|
| `LLM_PROVIDER` | `anthropic` or `openai` | `anthropic` |
| `LLM_MODEL` | model id | `claude-opus-5-5` (anthropic); **required** for openai |
| `ANTHROPIC_API_KEY` / `OPENAI_API_KEY` | credentials for the chosen provider | — |

## 3. Project layout

```
your-project/
├── raw/                      # immutable sources you add
├── wiki/                     # the OKF bundle (the LLM writes these — the source of truth)
│   ├── SCHEMA.md             #   authoritative conventions, included in every LLM prompt
│   ├── index.md  log.md      #   index (regenerated by scanning) + change log (reserved names)
│   └── sources/ entities/ concepts/ relationships/ overviews/
└── .agents/skills/llm-wiki/
    ├── SKILL.md  README.md
    ├── scripts/              # llm.py  prompts.py  util.py  wiki.py
    └── references/           # page-templates.md  schema-guide.md
```

All commands below run **from the project root** (the folder that holds `wiki/` and `raw/`). Every
subcommand also accepts `--root DIR` if you run from elsewhere.

## 4. One-time setup

1. Ensure the folders exist: `mkdir -p raw wiki/sources wiki/entities wiki/concepts wiki/relationships wiki/overviews`.
2. Ensure `wiki/SCHEMA.md` is present (the rulebook the scripts feed to the LLM).
3. Install the provider package and set your key (step 2) — only needed for `ingest`/`query`.
4. **Decide raw file names before the first ingest.** A raw name (minus date prefix and extension)
   becomes its permanent source ID. Prefer `YYYY-MM-DD-slug.ext`.

## 5. Ingest your sources

```bash
# add files to raw/, then:
python .agents/skills/llm-wiki/scripts/wiki.py ingest
```

What happens, oldest source first (a raw file is ingested when it has no source page yet; pass
`--all` to re-ingest everything):

1. **Source summary** → the LLM writes `wiki/sources/<slug>.md`.
2. **Topic pages**: every entity/concept that now has **3+ mentions** across the pages gets a page
   written or updated; below that it stays a *candidate* listed in `index.md`. Change the bar with
   `--min-mentions N`.
3. **Relationships**: a page is written when a source makes an explicit claim about how two things
   relate (and both endpoints already have pages, so links resolve).
4. **Overview**: written/refreshed when the big picture materially changes.
5. `index.md` is regenerated by scanning the pages, `log.md` is appended, and `lint` runs.

Flags: `--all` (re-ingest every file), `--min-mentions N`, `--prune` (see step 8).

A raw file with **no date prefix** is recorded in `log.md` with a suggested dated name; it is never
renamed automatically.

## 6. Inspect and validate

```bash
python .agents/skills/llm-wiki/scripts/wiki.py lint
```

`lint` audits the bundle and prints one line per finding:

- `ERROR` — broken link, missing `type`, a date in a `wiki/` filename, a footnote with no
  definition. Exit code 1.
- `WARN` — an entity/concept/relationship page with no inbound link (orphan).
- `PENDING` — a candidate still below the mention threshold. **Informational — not a problem.**

Rule of thumb: report anything that is not `PENDING`.

## 7. Query the wiki

```bash
python .agents/skills/llm-wiki/scripts/wiki.py query "what do my sources say about text2sql?"
```

The LLM picks the most relevant pages from `index.md`, reads them, and answers with citations to
concept IDs. The question is logged in `log.md`.

## 8. Revise or remove sources

- **Changed a raw file?** Re-ingest it with `wiki.py ingest --all` (without a state file there is no
  content-hash tracking, so `--all` re-writes the pages from the current raw files).
- **Removed a raw file?** Run `wiki.py ingest --prune`. For each withdrawn source the LLM rewrites
  every page that cited it so that source's facts and footnotes are gone, deletes the source summary
  and any emptied pages, and regenerates `index.md`. This is model-driven rather than exact, so skim
  the diff afterward.

## 9. Regenerate the index (no LLM)

```bash
python .agents/skills/llm-wiki/scripts/wiki.py index
```

Rebuilds `index.md` by scanning the pages — pages listed by ID, plus candidates with their mention
counts. Use it if the index looks stale after hand-edits.

## 10. Customising

- `scripts/prompts.py` — the LLM prompts. Each returns a finished Markdown page (the `query`
  selection and relationship planning return a tiny list/JSON). Edit the wording freely.
- `scripts/util.py` — raw discovery, slug/date resolution, mention counting, and `index.md`.
- `references/page-templates.md` — the page layout; `references/schema-guide.md` — frontmatter and
  naming rules.
- `wiki/SCHEMA.md` — the conventions, included in every LLM prompt. Change it to change the rules.

## Troubleshooting

| Symptom | Cause / fix |
|---|---|
| `Ingest stopped: The 'anthropic' package is not installed` | `pip install anthropic` (or set `LLM_PROVIDER=openai` + `pip install openai`). |
| `Anthropic auth failed` | `export ANTHROPIC_API_KEY=…` or `ant auth login`. |
| `unrecognized arguments: --root` | Put flags after the subcommand, e.g. `wiki.py ingest --root .`. |
| `Missing wiki/SCHEMA.md` | The bundle must carry its own schema; add `wiki/SCHEMA.md`. |
| `ingest` says "No new raw files" | Every raw file already has a source page; use `--all` to re-ingest. |
| `index.md` looks stale after hand-edits | Run `wiki.py index`. |
| A page came back wrapped in ``` fences or with stray prose | `wiki.py` strips a leading/trailing fence; if it persists, tighten the relevant prompt in `prompts.py`. |

## When to use the lite skill instead

Both skills are now stateless and both have the LLM write the pages; the difference is **automation**.
`llm-wiki` drives the model from scripts (good for many files, and gives you `lint`/`index`), and
needs Python + a provider key. `llm-wiki-lite` has no scripts at all — you ask the agent and it writes
the pages by hand (zero setup, best for a small corpus, no mechanical `lint`). The `wiki/` bundle is
identical in shape, so you can move between them over the same bundle.
